Table 2(c) Root Cause:

The server uses shell=True to invoke a system shell interpreter (cmd.exe on Windows or sh/bash on Linux) while directly embedding unsanitized user input. Command separators (such as &&, &, |, or ;) terminate the ping instruction and cause the operating system to execute chained arbitrary commands, streaming stdout back to the victim browser.

Table 2(e) Alternative Mitigations (Lecture Slides Theory):
  • Avoid the Shell Entirely: Use high-level programming language native system libraries (e.g., Python's socket library for ICMP/TCP reachability checks) rather than shelling out to external OS executables.
  • Parameterized Execution with Argument Vectors: When invoking OS processes, pass arguments as an explicit array of strings with shell=False. The OS treats each element strictly as data arguments, making shell meta-character evaluation impossible.
  • Allow-List Validation: Validate inputs strictly against expected character sets (such as regular expressions ensuring strictly valid IPv4/IPv6 addresses or alphanumeric domain names).
  • Principle of Least Privilege: Run the web server process under a heavily sandboxed, unprivileged dedicated system service account without administrative/root privileges or access to critical system binaries.
