💡 GET-Based CSRF Vulnerability

HTTP GET requests are defined by standard specifications (RFC 7231) to be safe and idempotent (retrieval only). When a web server modifies state (such as transferring money or deleting data) via GET requests, any HTML element that triggers a GET (such as <img src="...">, <iframe>, or <link>) can forge actions without user knowledge.

Mitigation: Strict adherence to HTTP verbs: state changes MUST only be accepted via POST/PUT/DELETE, protected by anti-CSRF synchronizer tokens and SameSite cookies.
