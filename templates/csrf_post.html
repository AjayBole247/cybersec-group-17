Table 2(c) Root Cause:

Web browsers automatically include ambient credentials (session cookies) with cross-origin requests. Because the server does not require any unpredictable, secret proof of user intent (such as an anti-CSRF token), an external malicious website can trick the browser into submitting a forged state-changing POST request on the authenticated victim's behalf.

Table 2(e) Alternative Mitigations (Lecture Slides Theory):
  • Anti-CSRF (Synchronizer) Tokens: A cryptographically secure, unpredictable, unique token generated per session/request. Stored on the server and verified on every sensitive state-changing POST/PUT/DELETE operation.
  • SameSite Cookie Attribute: Setting SameSite=Lax or SameSite=Strict instructs modern browsers not to attach session cookies to cross-site requests, effectively neutralizing CSRF at the browser level.
  • Re-Authentication / Step-Up Verification: Demanding password re-entry, biometric verification, or a multi-factor One-Time Password (OTP) before performing high-risk actions (e.g., fund transfers, password resets).
  • Avoiding State-Changing GET Requests: Adhering to HTTP RFC specifications by ensuring GET requests remain safe and idempotent (read-only), preventing trivial <img src="..."> exploitation.
