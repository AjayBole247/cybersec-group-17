Table 2(c) Root Cause:

Untrusted user input is stored directly in the database without encoding and later embedded into the HTML document using an unescaped context (| safe). The browser parses the malicious <script> or event handler tags as genuine client-side code, executing arbitrary JavaScript within every visiting victim's active session.

Table 2(e) Alternative Mitigations (Lecture Slides Theory):
  • Context-Aware Output Encoding: Encode dynamic data appropriate to the output context (HTML body, HTML attributes, JavaScript context, or CSS). Converts characters like <, >, ", ', and & into harmless entities.
  • Framework Auto-Escaping: Leverage web template engines (Jinja2, React, Angular) that enable strict contextual HTML auto-escaping by default.
  • Content Security Policy (CSP): HTTP response header (e.g. Content-Security-Policy: default-src 'self') that disables inline script execution and restricts script sources to trusted origins.
  • HttpOnly Cookie Flag: Directs browsers to block client-side JavaScript access to sensitive authentication cookies (document.cookie), mitigating session hijacking via XSS.
  • Safe DOM Sinks & Rich HTML Sanitizers: Use well-audited libraries like DOMPurify or bleach if HTML tags must be permitted, while avoiding dangerous DOM sinks like innerHTML or document.write.
