Table 2(c) Root Cause:

The application directly concatenates unfiltered input into a SQL statement that returns a 5-column result set. By injecting the UNION operator with an identical column count, an attacker appends rows from the confidential users table into the product catalog stream, exfiltrating administrative credentials and secret flags.

Table 2(e) Alternative Mitigations (Lecture Slides Theory):
  • Parameterized Queries / Prepared Statements: Ensures the database query planner treats user input strictly as a parameter value rather than executable SQL syntax.
  • Strict Allow-List Input Validation: Only allow predetermined valid categories (e.g. Hardware, Software, Books) by verifying input against a fixed server-side enum.
  • Least-Privilege Database Accounts: Partition database access so the catalog application user account lacks SELECT privileges on sensitive tables like users or transactions.
  • Safe Error Handling: Suppress verbose database error descriptions to prevent attackers from enumerating column counts and schema structures via trial-and-error UNION probes.
