Table 2(c) Root Cause:

Untrusted user input is directly concatenated into the SQL statement string before compilation. The input admin' -- breaks out of the intended data literal delimiter, injects SQL metacharacters, and turns the remainder of the query into a SQL comment (--), which eliminates password verification entirely.

Table 2(e) Alternative Mitigations (Lecture Slides Theory):
  • Parameterized Queries / Prepared Statements: Pre-compiles the SQL query structure in the database engine, ensuring input data is strictly bound as literal values and cannot alter command syntax.
  • Input Validation with Allow-Lists: Enforces strict regex validation (e.g., ^[a-zA-Z0-9_]{3,20}$) on usernames, rejecting unexpected quotes, dashes, or SQL keywords.
  • Principle of Least Privilege: Web application database accounts must only possess minimal required permissions (e.g., SELECT on specific tables, never DROP, ALTER, or administrator/DBA privileges).
  • Safe Errors: Suppresses detailed database engine error messages (such as SQLite/MySQL syntax stack traces) to prevent reconnaissance and error-based data leakage.
